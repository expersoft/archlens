Como ler as relações

usa (C4)

O consumidor chama ou depende do provedor.

A ⇢ B: "A usa B". A seta vai de quem chama para quem é chamado.

Ex.: Web usa API de Pedidos [REST].

linha tracejada, seta cheia no destino

serving (serve)

O provedor oferece funcionalidade para quem a usa.

A —> B: "A serve B" = "B usa A". A seta aponta para quem consome, no sentido oposto ao "usa" do C4.

Ex.: Hospedagem de contêineres serve API de Pedidos.

linha contínua, seta aberta no destino

realização

O concreto implementa o abstrato: processo realiza serviço, componente realiza app service, artefato realiza componente.

A ┄▷ B: "A realiza B". O triângulo fica no lado abstrato.

Ex.: Checkout Controller realiza Serviço de Checkout.

linha tracejada, triângulo vazio no destino

atribuição

Quem executa o quê: ator → papel, ativo → comportamento, nó → artefato implantado.

A ●→ B: "A executa / desempenha / hospeda B".

Ex.: Médico executa Realizar teleconsulta.

linha contínua, ponto na origem e seta cheia no destino

acesso

Comportamento ou componente que lê e/ou grava um dado (objeto passivo).

A ··> B: escrita aponta para o dado; leitura aponta para quem lê; leitura+escrita tem setas nas duas pontas.

Ex.: Checkout grava Pedido.

linha pontilhada, seta pequena

agregação

Todo–parte fraco: a parte pode existir sozinha ou em outros todos.

A ◇— B: "A agrega B". O losango fica no todo.

Ex.: Produto Venda Online agrega o serviço Compra online.

linha contínua, losango vazio no todo

disparo

Ordem temporal ou causal entre comportamentos.

A —▶ B: "A dispara B"; B começa depois de A.

Ex.: Checkout dispara Faturamento.

linha contínua, seta cheia no destino

Outras relações ArchiMate

composição

Todo–parte forte: a parte não existe sem o todo.

A ◆— B: "A contém B". O losango fica no todo.

Ex.: API de Pedidos contém Checkout Controller.

linha contínua, losango cheio no todo

fluxo

Transferência de informação, valor ou material entre comportamentos.

A ┄▶ B: "A passa algo para B".

Ex.: Faturamento passa a nota fiscal para Expedição.

linha tracejada, seta cheia no destino

influência

Um elemento de motivação afeta outro (positiva ou negativamente).

A ┄> B: "A influencia B".

Ex.: Requisito p95 < 2s influencia a meta Reduzir abandono.

linha tracejada, seta aberta no destino

especialização

A é um tipo mais específico de B (mesmo tipo de elemento).

A —▷ B: "A é um tipo de B".

Ex.: Entrega Expressa é um tipo de Entrega.

linha contínua, triângulo vazio no destino

associação

Relação genérica, sem semântica específica.

A — B: "A está relacionado a B".

Ex.: VPN associada ao Cluster.

linha contínua fina, sem setas

relação derivada

Relações derivadas (tracejado claro) aparecem quando elementos intermediários estão ocultos na visão, por camada, collapse ou granularidade. Elas resumem uma cadeia real de relações; o tipo mostrado é o mais fraco da cadeia.

Confusões comuns

serving × "usa" do C4
Mesma dependência, setas opostas. C4: "Web usa API" (seta Web → API). ArchiMate: "API serve Web" (seta API → Web). A seta do serving aponta para quem consome.
realization × serving
Realization liga o concreto ao abstrato do mesmo "assunto" (o componente implementa o serviço). Serving liga provedor e consumidor (o serviço é usado por um processo).
Para onde aponta a seta do access?
Escrita: para o dado. Leitura: para quem lê. Leitura e escrita: nas duas pontas. A linha é sempre pontilhada.
aggregation × composition
Losango cheio (composição): a parte não existe sem o todo. Losango vazio (agregação): a parte existe sozinha. Nos dois casos o losango fica no todo.
assignment × realization
Assignment diz quem executa (ator → processo, nó → artefato). Realization diz o que implementa o quê (processo → serviço).
Por que a análise de impacto sobe pela composição?
Na composição/agregação a parte sustenta o todo: se o Checkout Controller falha, a API de Pedidos (o todo) é afetada.
