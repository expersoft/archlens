# Agrupamentos e molduras — Plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** agrupamentos (ex.: Plataforma de Autorização, Plataforma de Crédito) como elementos `grouping` com membros
pelo campo `group`, visões recortadas por agrupamento (`groups.only`, `crossOnly`) e molduras desenhadas no C4 e no
ArchiMate, ligadas ou desligadas pela visão (`groups.frames`).

**Architecture:** `normalizeModel` lê `group`, valida e calcula o grupo efetivo (`groupId`, herdado pela hierarquia).
Um módulo novo, `query-groups.mjs`, concentra a leitura da spec `groups`, o recorte de nós e arestas e a lista de
molduras do IR; `query-c4` e `query-archimate` só o chamam. O layout transforma cada moldura em nó composto do ELK
(C4: uma por grupo; ArchiMate: uma por grupo × camada) e devolve `frames` com coordenadas; o render desenha as
molduras, a legenda e o painel. Merge, prévia, documento e sugestões tratam `group` como um campo comum.

**Tech Stack:** Node ≥ 18, ESM (`.mjs`), `node:test` + `node:assert/strict`, ELK vendorizado, rough.js vendorizado.
Nenhuma dependência nova.

**Spec:** `docs/superpowers/specs/2026-10-02-kb-groups-design.md`

## Global Constraints

- Node ≥ 18; sem dependências novas. Mensagens ao usuário em português; comentários de código em inglês.
- `grouping` é o tipo ArchiMate existente (`registry.mjs`, camada `other`); aceita `"grouping"` e `"archimate:grouping"`.
- Membro: campo `group` (string, id de um `grouping`) em qualquer elemento; um grupo por elemento; agrupamentos não
  se aninham; containers e componentes herdam o grupo do ancestral mais próximo que tenha um.
- Erros/avisos: `E_GROUP_REF`, `E_GROUP_NESTED`, `E_GROUP_REL`, `W_GROUP_EMPTY`, `E_VIEW_GROUP`.
- View spec: `groups: { only?: string[], crossOnly?: boolean, frames?: boolean }`; `frames` omitido → `true` se há
  `only`, senão `false`; `crossOnly` exige 2+ grupos em `only`.
- `grouping` nunca é nó de visão. Visões sem molduras e modelos sem agrupamentos produzem o mesmo IR e o mesmo layout
  de antes (nós sem grupo não ganham a chave `group`; o IR só ganha `groups` quando há molduras).
- ArchiMate: uma moldura por (grupo × camada), nunca atravessando faixas; estilo `bands` com molduras → `bands-flow`
  com aviso.
- Aparência: contorno contínuo, fundo tingido (`fill-opacity` .07 claro / .11 escuro), cor de paleta de 8 por
  `seedOf(id) % 8`, chip no canto superior esquerdo (C4: nome + "AGRUPAMENTO"; ArchiMate: só o nome).
- Git neste repositório (WSL) exige `export GIT_CONFIG_COUNT=1 GIT_CONFIG_KEY_0=safe.directory GIT_CONFIG_VALUE_0="$PWD"`;
  nunca alterar a config global. Branch `feat/kb-groups`.

## Decisões de detalhe (não estavam no spec; revisar)

1. **Agrupamento escondido pelo filtro de status** (ex.: `retired`): não gera moldura; os membros aparecem soltos.
   Em `groups.only`, um agrupamento escondido gera `E_VIEW_GROUP` (a dica menciona o filtro de status).
2. **Dentro de uma fronteira aberta** (visão de containers), os containers seguem a fronteira: a moldura envolve a
   fronteira pelo grupo do sistema; um container com `group` próprio diferente continua dentro da fronteira (o IR
   guarda o `group` dele, mas não há moldura própria).
3. **`depth` com `only`** acrescenta vizinhos; quando a visão também tem `focus`, o `depth` é do `focus` e o recorte
   por grupo não acrescenta vizinhos.
4. **Âncora (ArchiMate) e scope (C4 contexto)** sempre ficam na visão, mesmo fora dos grupos de `only`.
5. **Ordem no merge:** os `grouping` de um delta são processados antes dos demais elementos, para que o `group` dos
   membros já resolva para o id da base (duplicata `same`, alias ou nome).
6. **Paleta:** 8 cores por tema (`--g0`…`--g7`); grupos além de 8 repetem cores (o rótulo distingue).
7. **Fonte do chip:** nome 17px negrito; "AGRUPAMENTO" 15px com espaçamento (≥ `MIN_FONT`, para não disparar o
   alerta de legibilidade).

## Review Focus

1. **Agrupamento `retired`** com membros ativos → visão abre, sem moldura dele; `only` com ele → `E_VIEW_GROUP`. Teste na Task 2.
2. **Container com grupo diferente do sistema aberto** → layout não quebra; o container fica dentro da fronteira. Teste na Task 3.
3. **`crossOnly` sem nenhuma relação entre os grupos** → visão vazia (aviso existente), sem exceção. Teste na Task 2.
4. **Delta que põe um elemento num agrupamento inexistente** → plano bloqueado com `E_GROUP_REF`. Teste na Task 6.
5. **Visão ArchiMate com `layers` que esconde uma camada** → molduras só nas camadas presentes. Teste na Task 4.

`scripts/lib/model.mjs`, no objeto `node` (logo depois de `aliases`):


e, logo depois do `walk(...)` e antes da checagem de `pending`, uma checagem de tipo:

```js
  for (const n of elements.values()) {
    if (n.group !== null && typeof n.group !== 'string') {
      issue('error', 'E_SCHEMA', `"group" de "${n.id}" não é um id`, `${n.path}.group`, 'use o id de um elemento do tipo "grouping"');
```

Depois do laço que resolve `pending` (parents), antes dos aliases:

```js
  // Groupings: "group" names a grouping element; members inherit it down the parent hierarchy.
  for (const n of elements.values()) {
    if (n.group == null) continue;
    const g = elements.get(n.group);
    if (n.type === 'grouping') {
      issue('error', 'E_GROUP_NESTED', `o agrupamento "${n.id}" não pode pertencer a outro ("${n.group}")`, `${n.path}.group`,
        'agrupamentos não se aninham; remova "group" do agrupamento');
      n.group = null;
    } else if (!g || g.type !== 'grouping') {
      issue('error', 'E_GROUP_REF', g ? `"group" de "${n.id}" aponta para "${n.group}", que não é um agrupamento`
        : `"group" de "${n.id}" aponta para "${n.group}", que não existe`, `${n.path}.group`, 'use o id de um elemento do tipo "grouping"');
      n.group = null;
    }
  }
  const effectiveGroup = id => {
    const seen = new Set();
    for (let cur = id; cur != null && !seen.has(cur); cur = elements.get(cur)?.parent) {
      seen.add(cur);
      const g = elements.get(cur)?.group;
      if (g) return g;
    }
    return null;
  };
  for (const n of elements.values()) n.groupId = n.type === 'grouping' ? null : effectiveGroup(n.id);
```

```js
    const grp = ['from', 'to'].find(end => elements.get(r[end]).type === 'grouping');
```

```js
// Groupings in views: the "groups" spec (only / crossOnly / frames), the cut it makes and the frames it asks for.
import { viewError } from './query-util.mjs';

/** Normalized "groups" of a view spec: { only: Set|null, crossOnly, frames }. */
export function groupSpec(model, spec) {
  const g = spec.groups ?? {};
  if (!g || typeof g !== 'object' || Array.isArray(g)) {
    throw viewError('E_VIEW_GROUP', `"groups" da visão "${spec.key}" precisa ser um objeto`, 'ex.: { "only": ["plat-a", "plat-b"], "frames": true }');
  }
  let only = null;
  if (g.only !== undefined) {
    if (!Array.isArray(g.only) || !g.only.length) {
      throw viewError('E_VIEW_GROUP', `"groups.only" da visão "${spec.key}" precisa ser uma lista de agrupamentos`, 'ex.: ["plat-autorizacao", "plat-credito"]');
    }
    for (const id of g.only) {
      if (model.elements.get(id)?.type !== 'grouping') {
        throw viewError('E_VIEW_GROUP', `"${id}" em groups.only da visão "${spec.key}" não é um agrupamento visível`,
          'use ids de elementos do tipo "grouping"; um agrupamento fora do filtro de status da visão (ex.: retired) não pode ser listado');
      }
    }
    only = new Set(g.only);
  }
  const crossOnly = !!g.crossOnly;
  if (crossOnly && (!only || only.size < 2)) {
    throw viewError('E_VIEW_GROUP', `"crossOnly" da visão "${spec.key}" precisa de pelo menos dois agrupamentos em "only"`, 'liste os grupos cujas interações quer ver');
  }
  return { only, crossOnly, frames: g.frames ?? !!only };
}

/** Effective grouping of an element (its own or inherited); null when none. */
export const groupOf = (model, id) => model.elements.get(id)?.groupId ?? null;

/**
 * The cut of `only`: members of the listed groups plus neighbours up to `depth` along `edges`; with crossOnly, only
 * the members that take part in a relation between two different listed groups. `keepIds` always stay.
 */
export function cutByGroups(model, gs, nodeIds, edges, { depth = 0, keepIds = [] } = {}) {
  if (!gs.only) return new Set(nodeIds);
  const g = id => groupOf(model, id);
  const listed = id => gs.only.has(g(id));
  const inView = e => nodeIds.has(e.from) && nodeIds.has(e.to);
  const kept = new Set(keepIds.filter(id => nodeIds.has(id)));
  if (gs.crossOnly) {
    for (const e of edges) {
      if (inView(e) && listed(e.from) && listed(e.to) && g(e.from) !== g(e.to)) { kept.add(e.from); kept.add(e.to); }
    }
    return kept;
  }
  for (const id of nodeIds) if (listed(id)) kept.add(id);
  let frontier = [...kept];
  for (let d = 0; d < depth; d++) {
    const next = [];
    for (const e of edges) {
      if (!inView(e)) continue;
      if (frontier.includes(e.from) && !kept.has(e.to)) { kept.add(e.to); next.push(e.to); }
      if (frontier.includes(e.to) && !kept.has(e.from)) { kept.add(e.from); next.push(e.from); }
    }
    frontier = next;
  }
  return kept;
}

/** With crossOnly, only the edges between two different listed groups stay. */
export function cutEdges(model, gs, edges) {
  if (!gs.crossOnly) return edges;
  const g = id => groupOf(model, id);
  return edges.filter(e => gs.only.has(g(e.from)) && gs.only.has(g(e.to)) && g(e.from) !== g(e.to));
}

/** The view's frames: the visible groupings with members among `items` (nodes, boundaries), when frames are on. */
export function frameGroups(model, gs, items) {
  if (!gs.frames) return null;
  const ids = [...new Set(items.map(x => x.group).filter(id => id && model.elements.has(id)))];
  if (!ids.length) return null;
  return ids.map(id => {
    const g = model.elements.get(id);
    return { id, name: g.name, description: g.description ?? '', status: g.status ?? 'active' };
  });
}
```

```js
const GROUP_COLORS = 8;

/** A grouping frame: tinted box, chip with the name (C4 also says "AGRUPAMENTO"), preview mark on the chip. */
function groupFrame(fr, compact) {
  const c = seedOf(fr.id) % GROUP_COLORS;
  const sketchy = fr.status === 'draft' || fr.change === 'added';
  const cls = `gframe gc-${c}${sketchy ? ' sketchy' : ''}${fr.change ? ` ch-${fr.change}` : ''}`;
  const chipH = compact ? 36 : 56;
  const chipW = Math.ceil(Math.max(compact ? 120 : 170, fr.name.length * 17 * 0.58 + 52)) + (fr.change ? 30 : 0);
  const cx = fr.x + 14, cy = fr.y + 12;
  const mark = fr.change
    ? `<g class="mark m-${fr.change}"><circle cx="${f(cx + chipW - 18)}" cy="${f(cy + 18)}" r="11"/><text x="${f(cx + chipW - 18)}" y="${f(cy + 19)}" font-size="16" font-weight="700" text-anchor="middle" dominant-baseline="middle">${MARK[fr.change]}</text></g>`
    : '';
  return `<g class="${cls}" data-frame="${esc(fr.id)}">`
    + `<rect class="f-box" x="${f(fr.x)}" y="${f(fr.y)}" width="${f(fr.w)}" height="${f(fr.h)}" rx="18"/>`
    + (sketchy ? sketchOutline(fr.x, fr.y, fr.w, fr.h, 18, `frame:${fr.key ?? fr.id}`) : '')
    + `<g class="f-chip" tabindex="0" role="button" aria-label="Agrupamento ${esc(fr.name)}">`
    + `<rect x="${f(cx)}" y="${f(cy)}" width="${f(chipW)}" height="${chipH}" rx="10"/>`
    + `<circle class="f-dot" cx="${f(cx + 18)}" cy="${f(cy + 18)}" r="6"/>`
    + `<text class="f-name" x="${f(cx + 32)}" y="${f(cy + 19)}" font-size="17" dominant-baseline="middle">${esc(fr.name)}</text>`
    + (compact ? '' : `<text class="f-kind" x="${f(cx + 16)}" y="${f(cy + 42)}" font-size="15" dominant-baseline="middle">AGRUPAMENTO</text>`)
    + `${mark}</g></g>`;
}
```
